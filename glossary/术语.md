# 术语

- **Bodhi v2** — 一组智能合约，用代币发行、交易、行动和给币组织贡献激励。证据：`sources/full_text-20260630.txt:15-21`。
- **Action / 行动** — 贡献者在某个代币下提交的贡献内容。证据：`sources/full_text-20260630.txt:80-82`。
- **Fund / Give / 给币** — 持币者向行动贡献者给出代币。证据：`sources/full_text-20260630.txt:83-85`。
- **Bonding Curve** — 代币早期交易的固定价格曲线。证据：`sources/full_text-20260630.txt:37-44`。
- **Virtual AMM** — 用虚拟储备让初始池在无 ETH 的情况下近似传统 AMM。证据：`sources/full_text-20260630.txt:38-43`。
- **Migration / 迁移** — 售出 76% 后把 ETH 和剩余代币注入 DEX 并销毁 LP 的阶段。证据：`sources/full_text-20260630.txt:48-50`。
- **DEX** — Bodhi 内置的 Uniswap V2 fork。证据：`sources/full_text-20260630.txt:54-56`。
- **Funding 合约** — 存储 Arweave ID 并承载给币/claim 关系的合约。证据：`sources/full_text-20260630.txt:98-100`。
- **CacaoName** — 极简链上命名协议。证据：`sources/full_text-20260630.txt:106-108`。
- **rix** — 基于 Redis 的区块链索引框架。证据：`sources/full_text-20260630.txt:110-113`。
- **城市代币** — 以城市为代表物的代币，用来奖励改善城市的人。证据：`sources/full_text-20260630-2.txt:11`。
- **$TAIPEI** — 补充材料中用台北市作为城市代币的示例。证据：`sources/full_text-20260630-2.txt:11, 23`。
- **无市长城市** — 没有中心市长、却通过分布式激励运转良好的城市愿景。证据：`sources/full_text-20260630-2.txt:13-17`。
- **movement** — 补充材料中与城市、国家并列的潜在代币类型。证据：`sources/full_text-20260630-2.txt:21`。
- **给钱与给币** — 两类奖励会带来不同参与者、行动和项目气质。证据：`sources/full_text-20260630-2.txt:19`。
- **Bodhi v1** — 协议浏览器 + 基础协议，期望开发者在其上长出内容协议；被设计为“简陋”是设计选择。证据：`sources/full_text-20260713.txt:38-40`。
- **wishpool** — 2024 基于 v1 的代币驱动悬赏平台，是 v2 的血脉；创世 wish 因 vitalik 未参与而锁死，产品至今未开放。证据：`sources/full_text-20260713.txt:49-51`。
- **正方形哲学** — 接受自己是什么形状，才能做只有那种形状能做的事；创始人价值底座。证据：`sources/full_text-20260713.txt:65-68`。
- **反预判策略** — 不预判最优场景再发力，往前走再感受。证据：`sources/full_text-20260713.txt:12-16, 75-80`。
- **热闹大于整齐** — 产品设计原则：保持热闹、好逛、易发现，有机大于漂亮。证据：`sources/full_text-20260713.txt:91-106`。
- **pump.fun** — v1 之后几个月推出的 memecoin launchpad 特化版本，市面第一个；被创始人作为 v1 核心命题的反讽案例引用。证据：`sources/full_text-20260713.txt:42-44`。
- **virtual foundation** — v0 机制：每个 token 发币时预留的内置金库，有人贡献时由全体持币者投票决定是否用固定数量代币奖励。像自动 grant，太复杂、有隐患，后被换掉。证据：`sources/full_text-20260713-2.txt:43-49`。
- **任务/悬赏（v1 内测）** — 早于当前 v2 的机制：任何人发任务、投钱，做事的人提交成果领钱。清晰但实操复杂（分钱、有效期、退款无解），曾做过类似 Moloch DAO 的简化版仍被换掉。证据：`sources/full_text-20260713-2.txt:21-34`。
- **Moloch DAO** — 以太坊上一种极简的 grant/共享金库 DAO 模式；Bodhi v1 内测期曾按它做过任务机制的简化版。证据：`sources/full_text-20260713-2.txt:34`。
- **两种盒子** — 把“行动/任务”看作收钱盒子的比喻：已署名盒子（人先在、钱后投，= 当前 v2 行动给币）与未署名盒子（钱先到、人后认领，= 悬赏任务）。证据：`sources/full_text-20260713-2.txt:36-39`。
- **悬赏任务（未实现）** — “未署名盒子”形态，被创始人确认重要且仍在考虑，但当前未上线、形态未定。证据：`sources/full_text-20260713-2.txt:39-41`。
- **验证 / 市场驱动可信度** — Bodhi 不内建“做了没/是不是你做的”系统验证；可信度由贡献者自带证明、由给币的市场信号校准。验证问题在悬赏任务里更尖锐。证据：`sources/full_text-20260713-2.txt:51-61`。
- **发项目等于发币（理论）** — 创始人回答：在 bodhi 发项目理论上等于发币；成本下降使边界更复杂。证据：`sources/full_text-20260713-3.txt:13-15`。
- **低成本发币的监管模糊性** — 发币成本极低时，“发内容”与“发币/发证券”难以用传统范畴切割；法规可能尚未跟上。证据：`sources/full_text-20260713-3.txt:15-19`。
- **创建者与代币关系模糊化** — v2 中创建者可消失，他人塑造市值与含义；创建者与币的责任关系难界定（Doge 类比）。证据：`sources/full_text-20260713-3.txt:21-27`。
- **责任形态演进** — 普通合伙 → 有限责任 → crypto → bodhi v2；股东规模扩张伴随责任边界模糊化。证据：`sources/full_text-20260713-3.txt:29-39`。
- **有限责任公司（类比）** — source-005 用来说明：融资便利制度在兴起时曾被长期抨击，如今已成默认形态。证据：`sources/full_text-20260713-3.txt:35-37`。
- **领导者与执行者分工** — “昂贵的聪明人领导规划、便宜能做事的人完成工作”，创始人借 Cursor 多智能体实验主张这是跨人类历史与 AI 协作的成本最优分工，使中心化几乎不可避免。证据：`sources/full_text-20260721.txt:15-17`。
- **去中心化效率命题** — Bodhi 的总命题：借助 crypto 能否不依赖中心化结构，达到类似甚至更高的协作效率。目前只有直觉、没有证据。证据：`sources/full_text-20260721.txt:21-23`。
- **Cursor 多智能体实验（转述）** — 让不同 agents 组合基于 SQLite 文档用 Rust 重写 SQLite；都完成、品质相近但成本差异巨大（Fable 5 约 2 万美金 vs Opus 4.8 + Composer 2.5 约 1300 美金）。引自 Cursor 文章、待核实。证据：`sources/full_text-20260721.txt:9-13`。
